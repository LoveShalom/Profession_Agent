## 1. 摘要

**一句话**：把国内求职者散落各处的岗位信息与个人经历，变成"可检索、可匹配、可复用、可复盘"的两个库，并让简历从静态文档变成按 JD 动态生成的视图。

**三句话价值**
1. **信息资产化**：粘贴 JD → 18 字段结构化；录入/导入经历 → STAR + 技能标签 + 量化结果。
2. **决策有依据**：五维匹配评分 + 差距提示 + 证据可追溯，回答"投不投、差在哪、突出哪段经历"。
3. **隐私与合规**：本地优先，数据只在你自己的机器上；不自动投递、不爬取非公开数据。

**作品定位**【待填：希望它在简历上承担的角色，例如"AI 应用工程能力 + 产品闭环能力"】

---

## 2. 背景与问题

**核心症结**：国内求职缺少一个以"个人岗位库 + 个人经历库"为中心的闭环系统。岗位粘完就散、经历没有资产化、投递流程没有状态机、简历每次从零改。

7 个真实痛点（岗位分散 / 截止靠记 / 状态混乱 / 匹配靠感觉 / 素材散落 / 材料重复造 / 工具错位）与"信息层—决策层—执行层—工具层—心理层"五层分析，见 [mission.md](mission.md) §一、§二。

**为什么现有工具不解决问题**：国外工具不适配国内平台；自动化工具（爬取、批量投递）越过合规边界；Excel / Notion 模板只是容器，不提供结构化、匹配与生成能力。

## 4. 目标用户与场景

- **主要**：国内校招应届生、社招 1–5 年求职者、多平台并行者、多方向求职者、**重视隐私并愿意本地部署的用户**。
- **次要**：国企/体制内、海归回国、转行求职者。
- **非目标**：想全自动批量投递的人、想爬非公开数据的人、HR。
- **已知门槛（诚实说明）**：本地部署需安装 Docker；提供一键启动脚本降低门槛，完全非技术用户仍偏难（桌面打包记为观望项 W-01）。

详见 [mission.md](mission.md) §三。

**典型场景（3 条，用于演示与验收）**
1. 刷到心仪岗位 → 粘贴 JD → 30 秒内得到结构化记录与"待确认 2 个字段" → 确认入库。
2. 拿到面试通知 → 查看该岗位的匹配评分与差距提示 → 一键生成打招呼语与 3 条简历 bullet。
3. 周末复盘 → 看投递漏斗与提醒，决定下周补哪类经历。

## 5. 范围边界

**做**：JD 结构化与管理、经历库（手动 + 简历导入）、投递状态机与倒计时、AI 匹配与材料生成（可追溯、可弃答）、提醒（P2 最小版）、本地一键启动、BYOK。

**不做（Post-MVP）**：简历 PDF 导出与版本管理（P3）、合规数据源与浏览器插件（P4）、截图 OCR、托管多租户。

**明确不做（永久）**：自动投递/自动打招呼、爬取 BOSS/猎聘/智联、采集他人简历、微调/DPO、多 Agent 框架、自主浏览器 Agent。

依据见 [roadmap.md](roadmap.md) §7、§12.3。

## 6. 差异化与前沿性

**差异化（不容易被抄的部分）**：领域建模（双库 + 18 字段字典 + 13 状态机 + 证据链）、合规边界（只手动粘贴与官方数据）、本地优先（数据不出机 + BYOK）。

**前沿性（6 项，每项都对应真实痛点且都能进评测）**

| 能力 | 一句话 | 阶段 |
|---|---|---|
| 验证器优先生成（含弃答） | 规则验证 → LLM 复核 → 修复 → 弃答，而不是"生成后检查" | I6 |
| 自一致性置信度 | K=3 采样一致率替代"LLM 自报置信度" | I1 |
| 用户风格检索 | 用你自己确认过的产物做 few-shot，越用越像你 | I6 |
| 求职记忆固化 | 事件流 → 长期记忆卡（偏好/被拒模式/有效话术） | 触发式 |
| 查询分解与多跳检索 | JD 要求拆成子查询逐项召回，输出"该补哪段经历" | 触发式 |
| MCP Server | 让项目成为 Agent 生态的能力提供方（本地 stdio） | P5 |

技术细节见 [tech_stack.md](tech_stack.md) §3.9；工时与并入方式见 [roadmap.md](roadmap.md) §12。

## 7. 总体技术方案

**分层**：客户端（Next.js + 可选插件）→ 应用层（Server Actions / 状态机 / 调度）→ **AI 能力层（Provider 适配层 + 能力探测 + 降级链）** → 数据层（本地 Supabase 栈）→ 外部层（用户自选模型服务）。

**关键选型**：Next.js 15 + TS + Tailwind + shadcn/ui；Supabase 本地栈（Postgres + pgvector）；Vercel AI SDK + Function Calling + Zod；BGE-M3（可 BYOK）；Docker Compose 一键启动；Promptfoo + Ragas + LangFuse 做评测与可观测。

**首批 ADR（10 条）**：Supabase 选型、pgvector、本地优先部署、FC+Zod、状态机自研、react-pdf、BYOK 设计、验证器优先、自一致性、MCP 边界。

架构图与完整清单见 [tech_stack.md](tech_stack.md) §2、§3、§4。

## 8. 数据与隐私模型

- **本地优先**：岗位、经历、简历、生成物默认全部存于本机容器；作者不托管、不接收、不存储任何用户数据。
- **唯一外发**：你主动触发 AI 功能时，必要文本发送给**你自己配置**的模型服务商；用 Ollama 可完全离线。
- **凭证**：API Key 以 AES-256-GCM 密文存储，主密钥在服务端 `.env`；**只写不回读**；日志与可观测全程脱敏。
- **删除**：`docker compose down -v` 即彻底删除，不需要"申请删除"流程。
- **数据流向告知**：粘贴/上传时检测手机号、邮箱、身份证并提示"这段文本会被发送"，提供"脱敏后发送"开关。

依据见 [tech_stack.md](tech_stack.md) §5。

## 10. 质量与评测

**评测 harness（本项目对"harness"的具体落地）**
- 数据集：JD 抽取金标准 50 条、经历 STAR 30 条、匹配对 100 条、话术质量 30 条、幻觉集 50 条。
- 门禁：CI 上 PR 抽样、`main` 全量；阈值不达标即失败。
- 口径：18 字段**宏平均** + 归一化比对 + 缺失字段排除 + 关键字段单独统计（[tech_stack.md](tech_stack.md) §12.4）。
- 新增分层判定：**置信度分层准确率**（高置信 vs 低置信差 ≥15pt）、**弃答率**、**风格检索增益**。

**功能级验收**：每个功能一份功能规范，含"功能规格与分支 / 收集需求 / 任务计划 / 如何验收评分"四节，按 100 分评分卡打分（≥85 通过 / 70–84 有条件通过 / <70 不通过）。模板见 [features/_TEMPLATE.md](features/_TEMPLATE.md)；已编写两份：[F-01 工程地基与 Provider 适配层](features/F-01-bootstrap.md)（I0，12h）、[F-02 JD 入库闭环](features/F-02-jd-ingest.md)（I1，30h）。P0 清单与规范队列见 [../docs/adr/p0_features.md](../docs/adr/p0_features.md)。

## 11. 风险与合规

**主要风险**：抽取准确率不达标、简历解析版式兼容、本地部署门槛、时间不足（降级链：I7 提醒 → 跟进建议 → 面试题 → 雷达图 → 匹配 → 话术）、Provider 兼容性差异、密钥泄漏（P0 红线）。

**合规底线**：不自动登录/批量投递、不绕验证码、不采集他人信息、只处理用户主动提供或公开数据、不用于模型训练、AI 只建议不执行。

完整表见 [roadmap.md](roadmap.md) §9、[tech_stack.md](tech_stack.md) §5、§11。
