## 1. 功能规格与分支

### 1.1 用户故事

- **US-1**：作为求职者，我希望把岗位卡片从「待投递」拖到「已投递」，以便不用逐个点开改状态。
- **US-2**：作为求职者，我希望误操作（拖错列）能一键回退，并且**回退要留痕**，以便复盘流程而不是靠记忆。
- **US-3**：作为求职者，我希望一眼看到"哪几个快截止了、哪几个该跟进"，以便今天先做最紧的事。
- **US-4**：作为求职者，我希望重复粘贴同一个岗位时能选择「合并到已有」或「忽略」，以便台账不出现双胞胎。
- **US-5**：作为求职者，我希望看到一个岗位的完整时间线（什么时候投的、几轮面试、什么时候被拒），以便写复盘/准备下一轮。

### 1.2 输入 / 输出契约

| 项 | 内容 |
|---|---|
| 状态枚举 | 13 个，见 §1.4（唯一真源移到 `src/lib/status.ts`，中文文案集中维护） |
| 流转请求 | `PATCH /api/jobs/[id]/status { to: Status, note?: string }`；`note` 在**回退**与**进入终态**时必填（≥2 字） |
| 事件日志 | 每次流转写一行 `job_events { from_status, to_status, note, occurred_at }`，与 `jobs.status` 更新**同一事务** |
| 列表/看板查询 | `GET /api/jobs?status=<Status>&sort=deadline|priority|updated`；看板一次取全量非终态（<200 条时不分页） |
| 事件查询 | `GET /api/jobs/[id]/events?limit=50` → 倒序时间线 |
| 去重响应 | 入库时 `status: 'duplicate'` + `duplicateOf`（I1 已有）→ I3 增加两个动作：`merge`（把新 JD 的差异字段并入旧记录并记事件）/ `forceCreate`（已支持） |
| 错误码 | `E_ILLEGAL_TRANSITION`（非法流转）、`E_NOTE_REQUIRED`（回退/终态缺备注）、`E_NOT_FOUND`、`E_CONFLICT`（并发修改） |
| 契约版本 | `job-status-v1`；新增状态需改枚举 + 迁移 CHECK + UI 列 |

### 1.3 分支与变体矩阵

**A. 流转判定（核心，必须穷举）**

| 分支 | 条件 | 行为 |
|---|---|---|
| 同状态 | `to === from` | 幂等：不写事件、返回 200 + `unchanged: true` |
| 向前跨步 | 目标行序 > 当前行序 | 允许（如 `applied → interviewing`），写事件 |
| 向前逐步 | 行序 +1 | 允许 |
| **回退** | 目标为**更早的非终态** | 允许，但 `note` 必填（≥2 字），事件标 `is_rollback: true` |
| 进入终态 | 目标 ∈ `accepted/rejected_by_company/withdrawn/expired` | 允许，`note` 必填 |
| 终态重新激活 | 当前为终态、目标为非终态 | 允许，`note` 必填，事件标 `is_reactivation: true` |
| 终态 → 另一终态 | 如 `withdrawn → expired` | **拒绝**（`E_ILLEGAL_TRANSITION`），避免语义打架 |
| 非法目标 | 不在 13 枚举内 | 400 `E_ILLEGAL_TRANSITION` |
| 并发 | 请求里的 `fromStatus` 与库内不一致 | 409 `E_CONFLICT`，前端刷新看板（乐观并发） |
| 批量流转 | 看板多选后拖拽（Could） | 逐条事务 + 汇总报告 |

**B. 看板交互**

| 分支 | 行为 |
|---|---|
| 拖拽到同列 | 无操作 |
| 拖拽到非法列（终态列 → 非终态列需备注） | 弹出备注输入框；取消则回弹 |
| 键盘操作 | 选中卡片后 `←/→` 移动、`Enter` 确认（**无障碍替代拖拽**，必做） |
| 卡片密度 | 列内按 `deadline` 升序（无截止排最后），再按 `priority` |
| 列显示 | 默认显示 9 个非终态列；终态收进「已结束」折叠区（避免看板过宽） |
| 空列 | 显示占位提示，仍是有效放置目标 |
| 移动端 | 单列纵向视图 + 状态下拉（不做拖拽） |

**C. 去重合并（A4/B6 收尾）**

| 分支 | 行为 |
|---|---|
| 指纹相同（I1 已实现） | 提示三选一：查看已有 / 合并 / 仍要新建 |
| 选择合并 | 保留旧记录 id；**新 JD 中非空且旧的为空的字段**补齐；`raw_text` 追加（带分隔符）并记事件 `note: '合并重复 JD'` |
| 选择新建 | 已有 `forceCreate` |
| 指纹不同但标题/公司高度相似 | 显示"可能重复"黄色提示，**不阻塞**（向量兜底留接口，I5 实现） |

**D. 截止倒计时与排序（F9）**

| 分支 | 展示 |
|---|---|
| 有截止日 | `T-N 天`；≤3 天红色、≤7 天黄色 |
| 今天截止 | 「今天截止」红色 |
| 已过期未投 | 提示"已过期，建议标为已结束"，**不自动改状态**（状态机只由用户驱动） |
| 无截止日 | 显示「未提供」，不参与倒计时排序 |
| `text_only` | 显示原文（如"招满为止"） |

**E. 异常与一致性**

| 分支 | 行为 |
|---|---|
| 事件写失败 | 整体回滚（同一事务），状态不变 |
| 岗位被软删 | 不允许流转（`E_NOT_FOUND`） |
| 浏览器离线 | 前端保留乐观更新 + 重试队列（最多 3 次），失败回滚 UI |

### 1.4 状态与流转（G-03，行序即先后）

```
saved(收藏) → to_apply(待投递) → applied(已投递) → assessment(待测评) → written_test(待笔试)
→ test_done(已笔试) → interviewing(面试中) → offer_pending(待Offer) → offered(已Offer)
→ accepted(已接受)✔  |  rejected_by_company(被拒)✔  |  withdrawn(本人放弃)✔  |  expired(已过期)✔
```

规则：

1. 允许**按行序任意跨步向前**；允许**回退到更早的任意非终态**（必须备注 + 记事件）。
2. 终态集合 = `accepted` / `rejected_by_company` / `withdrawn` / `expired`；终态可**重新激活**到任意非终态（必须备注）。
3. `priority`（高/中/低）与状态**正交**：互不推导（tech_stack §3.5）。
4. 状态只由**用户操作**驱动：不因到期/超时自动迁移（避免"我没动它却变了"）。

### 1.5 边界与非目标

- **不做**：提醒/通知（含面试与截止提醒）——属 I7（P2 后置，A-08 裁决）；本增量只做**纯展示**倒计时。
- **不做**：面试记录表 `job_interviews`（本增量用事件日志 `note` 记录轮次）——建表与结构化面试反馈放到 I6 前，理由：无提醒时"面试记录"价值有限，且 I6 材料生成才真正消费面试素材。
- **不做**：自动过期 / 自动放弃（状态只由用户驱动）。
- **不做**：多岗位批量导入看板拖拽的撤销栈（只做单条回弹 + 事件回退）。
- **不做**：XState 等状态机库（ADR-0005：13 状态自研纯函数更可测）。

## 2. 收集需求

### 2.1 需求来源与方法

| 来源 | 结论 |
|---|---|
| `tech_stack §3.5`（G-03 裁决） | 13 状态枚举、行序跨步/回退规则、终态重新激活、priority 正交 |
| `tech_stack` 数据表 | `job_events { from_status, to_status, note, occurred_at }`；`jobs.status` 已存在但缺 CHECK |
| `roadmap I3` | 出口标准：看板拖拽流转；回退可查日志；重复粘贴被识别并可合并/跳过 |
| ADR-0005 | 自研轻量状态机（纯函数 + 单测），不引入 XState |
| 历史裁决 C-01 | 状态变更不做版本管理；软删 + 事件日志足够 |

### 2.2 验收场景（Given / When / Then）

- **AC-1 看板流转**：Given `to_apply` 的岗位，When 拖到「已投递」，Then 状态变为 `applied` 且新增 1 条 `job_events`。
- **AC-2 跨步前进**：Given `applied`，When 直接拖到「面试中」，Then 成功（允许跨步）。
- **AC-3 回退留痕**：Given `interviewing`，When 回退到 `applied` 并填备注，Then 成功且事件标 `is_rollback`；When 不填备注，Then 400 `E_NOTE_REQUIRED`。
- **AC-4 终态规则**：Given `withdrawn`，When 拖到 `expired`，Then 409/400 拒绝；When 重新激活到 `applied` 并填备注，Then 成功且事件标 `is_reactivation`。
- **AC-5 幂等**：Given 状态已是 `applied`，When 再次请求 `applied`，Then 200 `unchanged: true`，不新增事件。
- **AC-6 并发**：Given 看板停留在旧状态，When 该岗位已被另一处改动，Then 409 `E_CONFLICT` 并刷新。
- **AC-7 时间线**：Given 有 5 次流转，When 打开详情页，Then 按时间倒序展示 5 条（含 from→to、备注、时间）。
- **AC-8 去重合并**：Given 重复 JD，When 选择「合并」，Then 旧记录补齐新字段且 `raw_text` 追加，并记事件「合并重复 JD」。
- **AC-9 倒计时**：Given 截止在 2 天后，When 查看看板，Then 显示红色「T-2 天」；已过期显示过期提示但不改状态。
- **AC-10 键盘可达**：Given 键盘用户，When 选中卡片按 `→`，Then 卡片进入下一合法列（与拖拽等价）。

### 2.3 非功能需求

| 项 | 要求 |
|---|---|
| 性能 | 看板首屏 ≤ 1.5s（200 岗位内）；单次流转 ≤ 300ms |
| 一致性 | 状态更新与事件写入**同一事务**；事件不可修改/删除，只追加 |
| 可追溯 | 任一岗位可查完整时间线；回退/重新激活有标记位 |
| 可访问性 | 键盘可完成全部流转（拖拽非唯一路径） |
| 可测试 | 状态机为**纯函数**，转移矩阵可穷举（13×13=169 组合全测） |

### 2.4 优先级（MoSCoW）

- **Must**：13 状态枚举 + 转移规则、`job_events` 迁移、流转 API、看板（拖拽 + 键盘）、回退备注、时间线、倒计时展示、AC-1~AC-7。
- **Should**：去重合并（AC-8）、看板终态折叠区、移动端下拉视图。
- **Could**：批量拖拽、撤销栈、看板筛选（按城市/优先级）。
- **Won't**：提醒通知（I7）、面试记录表（I6 前）、自动过期。

### 3.4 技术选型：看板拖拽（✅ 已裁决：方案 A 零依赖）

| 方案 | 依赖 | 体验 | 可访问性 | 推荐度 |

| **A. 零依赖（原生 draggable + 键盘）** | 0 | 够用（无动画） | 键盘操作独立实现，反而更完整 | ⭐ 建议先做 |
