**一句话定义**：你指定一个文件夹，工具把岗位库导出成能直接用 Excel 打开、**也能在 Excel 里改回来**的台账。

> 需求出处：用户裁决"用户在使用时，是设置一个工作区，这个工作区可以是一个文件夹"、
> "工具可以创建表格文件，然后按照关键词等等写入"、"表格应该允许用户修改，Agent 是辅助"
> （[decisions_log §12](../../logs/decisions_log.md)）。P1 裁决把它移出 I1（§14）。
> 设计基线在 [F-02 §2.5.1](F-02-jd-ingest.md) 保留，本规范是它的落地版。

## 1. 功能规格与分支

### 1.1 用户故事

- **US-1**：作为求职者，我希望在 Excel 里一眼看到所有岗位（公司/岗位/城市/薪资/截止/技能/待确认），
  以便按城市筛选、按截止日期排序，而不是在网页里一条条点。
- **US-2**：作为求职者，我希望直接在 Excel 里改状态、优先级、下一步，甚至修正 AI 抽错的字段，
  保存后系统能读到，以便用我最熟悉的工具管理求职台账。
- **US-3**：作为求职者，我希望台账能备份/同步网盘/发给别人看，以便换电脑或分享时不用重新录。
- **US-4**：作为求职者，我希望删掉整个工作区也不会丢数据，以便我不小心清空文件夹时能一键恢复。

### 1.2 输入 / 输出契约

| 项 | 内容 |
|---|---|
| 输入（配置） | `WORKSPACE_DIR`（`.env`，默认 `./data/workspace`）；设置页可改并即时生效 |
| 输入（同步） | 用户编辑后的 `岗位管理表.csv`（可能被 Excel 重排格式/插入列/改日期格式） |
| 中间产物 | `ParsedTable { header: string[], rows: Array<{ rowNumber, values, revision }>, unknownColumns: string[] }` |
| 输出（导出） | 工作区文件：`岗位管理表.csv`、`技能明细表.csv`、`README.txt`、`原始JD/*.md`、（有冲突时）`同步冲突记录.csv` |
| 输出（同步） | `SyncReport { created, updated, skipped, deletedProtected, conflicts, warnings }` |
| 错误码 | `E_WORKSPACE_UNWRITABLE`（路径不存在/无权限）、`E_FILE_LOCKED`（Excel 占用）、`E_HEADER_MISSING`（缺 `岗位ID` 列）、`E_DB_UNAVAILABLE` |
| 契约版本 | `workspace-table-v1`（列集合与语义变更需升版本） |

**主表列（23 列）与权限**

| 列 | 权限 | 说明 |
|---|---|---|
| `岗位ID` | 🔒 只读（同步键） | 改动视为新增行或错误 |
| `_rev` | 🔒 只读 | 修订号，冲突检测用 |
| `状态` `优先级` `下一步` `下一步时间` `备注` | ✏️ 用户可改 | 表格主用途 |
| `公司` `岗位` `城市` `招聘类型` `届别` `学历` `经验` `薪资下限` `薪资上限` `薪资月数` `截止时间` `技能·明确(必须)` `技能·明确(加分)` | ✏️ 用户可改 | **= 人工校准**：回写 DB 并清除对应 `review_flags` |
| `剩余天数` `匹配分` `待确认字段` `技能·推测` `[只读]` | 🔒 只读 | 计算/推演产物，重导出时恢复 |
| 用户自建新列 | 🛡️ 保留 | 工具不读不写 |

### 1.3 分支与变体矩阵

**A. 导出**

| 分支 | 条件 | 行为 |
|---|---|---|
| 首次导出 | 工作区不存在 | 创建目录与 4 个文件 + `README.txt` |
| 覆盖导出 | 已有文件 | 全量重写；**保留** `原始JD/` 与用户自建列（按 `岗位ID` 回填） |
| 无岗位 | `jobs` 为空 | 只写表头 + README 提示"还没有岗位" |
| 工作区不可写 | 路径无效/只读盘 | `E_WORKSPACE_UNWRITABLE`：提示改路径，**不阻塞应用** |
| 技能明细 | 某岗位无技能 | 该岗位在长表里无行（不写空行） |

**B. 同步（回读）**

| 分支 | 条件 | 行为 |
|---|---|---|
| 正常修改 | 文件 `_rev` == DB `_rev` 且值不同 | 回写 DB，`_rev + 1`，计入 `updated` |
| 冲突 | 文件 `_rev` < DB `_rev` 且值不同 | **采用用户值**（人优先），写 `同步冲突记录.csv` 并在 UI 提示 |
| 新增行 | `岗位ID` 不存在 | 需 `公司`+`岗位` 才能建；缺字段 → `skipped` + 警告 |
| 删除行 | DB 有、文件无 | **不删 DB**，下次导出补回，提示"检测到 N 行被删除，已恢复" |
| Excel 未关闭 | 存在 `~$岗位管理表.csv` | `E_FILE_LOCKED`：提示"请先在 Excel 中关闭文件"，不写盘 |
| 表头缺失 | 无 `岗位ID` 列 | `E_HEADER_MISSING`：拒绝同步（防误把别的表当台账） |
| 只读列被改 |  `匹配分` 等被手改 | 不采纳，重导出时恢复；`warnings` 记录 |
| 格式漂移 | 日期 `2026/11/20`、数字 `15,000`、全角 `；` | 宽容解析后归一 |
| 新增未知列 | 用户插了一列 | 原样保留，不参与同步 |
| 数据库不可用 | 连接失败 | `E_DB_UNAVAILABLE`：提示 `npm run setup`，不动表格文件 |

**C. 编码与安全**

| 分支 | 行为 |
|---|---|
| CSV 编码 | **UTF-8 带 BOM**（无 BOM 时 Windows Excel 中文乱码） |
| 字段转义 | RFC4180：含逗号/引号/换行时加引号并转义 |
| 公式注入 | 以 `=` `+` `-` `@` 开头的值前置 `'` |
| 敏感信息 | 表格不含密钥；`原始JD/` 含原文，README 提示"该目录含个人信息，勿公开分享" |

### 1.4 状态与流转

```
配置工作区 → 导出（export） ⇄ 用户在 Excel 编辑 ⇄ 同步（sync）
                                    ↓
                              冲突 → 用户优先 + 记录
```

- 导出触发：入库成功、改状态、手动 `npm run export`
- 同步触发：**仅手动** `npm run sync`（或界面按钮）——不自动回读，避免与 Excel 抢文件
- 工作区删除后：任意一次导出即重建（DB 是唯一真相源）

### 1.5 边界与非目标

- **不做**：多工作区（W-07）、把状态机映射成物理目录（会产生双真相源）、XLSX 着色（R5-01 裁决改用分列）
- **不做**：表格内编辑技能明细表（长表只读，技能编辑走主表列）
- **不做**：实时文件监听（`fs.watch` 会与 Excel 的写盘节奏冲突）

## 2. 收集需求

### 2.1 需求来源与方法

| 来源 | 结论 |
|---|---|
| 用户裁决（decisions_log §12） | 工作区=文件夹；CSV；存原始 JD；**表格允许用户修改，Agent 是辅助** |
| 用户裁决 P1（§14） | 移出 I1，成为独立增量（I1.5） |
| R1-01/R5-01 | 用 CSV；不做着色，改为**分列**区分明确/推测 |

### 2.2 验收场景（Given / When / Then）

- **AC-1 生成**：Given 已配置 `WORKSPACE_DIR`，When 导出，Then 4 个文件生成，`岗位管理表.csv` 带 UTF-8 BOM，**Excel 打开中文正常**。
- **AC-2 编辑回写**：Given 在 Excel 改 `状态`/`优先级`/`下一步`/抽取字段，When 同步，Then DB 已更新；改过的抽取字段从 `review_flags` 移除。
- **AC-3 只读列保护**：Given 手改 `匹配分`，When 同步，Then 不采纳、重导出恢复。
- **AC-4 删行安全**：Given 删掉一行，When 同步，Then DB 数据仍在、重导出补回并提示。
- **AC-5 冲突**：Given 文件与 DB 同字段都改，When 同步，Then 采用文件值 + 写冲突记录。
- **AC-6 健壮性**：Excel 未关闭 → 可操作提示；`2026/11/20`、`15,000`、全角 `；` 正确解析；`=` 开头值被转义。
- **AC-7 恢复**：Given 删除整个工作区，When 再导出，Then 文件与数据完整恢复。

### 2.3 非功能需求

| 项 | 要求 |
|---|---|
| 性能 | 1000 岗位导出 ≤ 2s；同步 ≤ 3s |
| 数据安全 | 同步前先写 `.backup/岗位管理表.<时间戳>.csv`（便于回滚） |
| 可恢复 | 工作区可整体删除并重建 |
| 可观测 | `SyncReport` 打印到终端并可选写 `同步日志.csv` |

### 2.4 优先级（MoSCoW）

- **Must**：导出主表+技能表、BOM、列级权限、状态/字段回写、`_rev` 冲突检测、删行保护、锁文件检测。
- **Should**：原始 JD 快照、同步前备份、冲突记录文件。
- **Could**：用户自建列保留、`--dry-run` 预览同步计划。
- **Won't**：XLSX、文件监听、表格内编辑技能长表。

### 2.5 待澄清问题

| 问题 | 影响 | 默认 |
|---|---|---|
| 同步前的备份保留几份？ | 磁盘占用 | 保留最近 5 份（`.backup/` 自动清理） |
| 导出时是否也导出"已删除"岗位？ | 用户预期 | **不导出**（`deleted_at` 非空的不出现） |
