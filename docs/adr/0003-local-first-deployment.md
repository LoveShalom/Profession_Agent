# ADR-0003：部署形态选"本地优先 + 无状态只读展示页"，不做托管多租户

- 状态：已采纳（C-10 裁决）
- 日期：2026-10-15（裁决）/ 2026-10-16（I0 实施）
- 关联：[decisions_log.md §9](../../logs/decisions_log.md)、[tech_stack.md](../../spec/tech_stack.md) §3.8

## 背景

项目所有者明确提出："**我希望我这边并不需要存储用户信息**——用户从 GitHub 下载项目 → 自己本地管理隐私信息 → 工具纯粹辅助管理。"

这直接否定了"作者托管、用户注册"的常规 SaaS 形态，也否定了随之而来的 Auth / RLS / 配额 / 隐私政策 / 成本模型。

## 选项

| 方案 | 数据位置 | 作者责任 | 展示能力 |
|---|---|---|---|
| A. 纯本地，不做在线实例 | 全在本机 | 零数据、零成本 | 只能靠视频与文档 |
| B. **本地为主 + 无状态只读展示页（本 ADR 采纳）** | 全在本机；展示页不落库 | 零用户数据、零模型成本 | 面试官可点开看 |
| C. 本地 + 可选托管（仅 BYOK） | 用户数据仍在作者 DB（虽然作者不看） | 仍承担存储与合规责任 | 完整 |

## 决定

采用 **方案 B**：

- 主路径 = 用户 clone → `npm run setup` → 数据全在本机容器；作者不接收任何用户数据；
- 在线只保留一个**无状态只读展示页**（固定示例数据、无注册、无写入路径）；
- 托管多租户**明确不做**。

## 后果

- ✅ 隐私叙事从"我们如何保护你的数据"变成"**数据不离开你的机器**"（更强且更易证明）。
- ✅ 风险面大幅缩小：移除多租户隔离、邀请码、per-user 配额、模型成本预算等一整块复杂度。
- ✅ 国内可达性不再是阻塞项（本地运行不需要访问 Vercel/Supabase 云端）。
- ⚠️ 使用门槛转移到用户侧（需装 Docker）→ 已用 `npm run setup` 一键脚本缓解，非技术用户仍偏难，
  桌面打包记为观望项 W-01。
- ⚠️ 多账号模式作为**可选能力**保留（`ENABLE_AUTH=true`），代码与策略已就绪但不作为默认路径。
- 实现落点：`src/lib/tenant.ts`（单用户固定归属 ID）、`src/lib/llm/guard.ts`（出站白名单/私网拒绝）、
  `supabase/migrations/0001_init.sql`（RLS 策略就绪但默认不生效）。
