### Q-07 🟠 熟练度枚举用几级（**代码已按 A 实现，待追认**）

- **现状**：F-02 已交付的 `job_skills.proficiency` 枚举为 **5 值**
  `expert / proficient / familiar / basic / unknown`（精通/熟练/熟悉/了解/未标注），即选项 A。
- **选项**：
  - **A. 保持 4 级 + unknown（当前实现）**：贴合 JD 原文用词，可映射权重 1.0/0.8/0.6/0.4。
  - B. 简化为 3 级：精通 / 熟练 / 了解（把"熟悉"并入"熟练"）。抽取更稳、标注更省，但丢失区分度。
  - C. 只做二元：必须 / 加分，不做熟练度。最省，但回答不了"要到什么程度"。
- **建议**：**追认 A**。中文 JD 里"熟悉"与"熟练"确实被区分使用；若实测两者混淆 >20%，再降为 B
  （届时需改 schema 枚举 + 迁移 + 评测标注集，约 2h）。
- **影响**：若改 B/C，需回改 F-02 的 `SKILL_PROFICIENCY`、DB CHECK 约束、抽取 prompt、评测标注集。

### Q-08 🟠 "我的水平"从哪来（决定差距表能否成立）

- **现状**：技能差距表需要"我是否具备 + 我的水平"；F-10（I5）时经历库（F-05，I2）已存在，
  但用户可能尚未录入全部技能。
- **选项**：
  - **A. `我的技能.csv` 自评（当前设计）**：工作区（F-03）放一张可编辑表 `技能, 我的水平`，用户自填。
  - B. 设置页勾选：结构化输入更准，但要多做一个页面。
  - C. 只用经历库：`experiences.skills` 为准，缺失技能视为"未具备"。
  - D. A + C 混合（推荐细化）：以经历库为主、自评为补充。
- **建议**：**D**（F-03 先落地 `我的技能.csv` 占位，I2 打通后以经历库为主）。
- **影响**：F-10 的数据来源、工作区文件数（+1 张表）、差距分可信度。

### Q-09 🔴 截图 OCR 是否引入本地引擎（新增，2026-10-25）

- **现状**：F-04 的 OCR 有两条路——视觉模型（VLM）读图，或本地 OCR 引擎识别。
  VLM 零新依赖，但**用户必须有一个支持视觉的模型**（DeepSeek 文本模型不支持）；
  本地 OCR 让"只用文本模型"的用户也能用截图输入，但要引入依赖与体积。
- **选项**：
  - **A. VLM-only（我的建议，MVP）**：0 新依赖；无视觉模型时给明确引导。风险：这部分用户用不了截图输入。
  - B. VLM + `tesseract.js`：+1 依赖（WASM ~10MB），中文 90–93%（懒加载，不拖首屏）。
  - C. VLM + `PaddleOCR-onnx`：+2 依赖（模型 20–40MB），中文 96%+。
- **建议**：先 **A**（8h 内可交付），UI 明确提示"截图输入需要视觉模型"；
  若实测 VLM 识别质量不足或有用户反馈没有视觉模型，再升级 B（+3h，按需下载引擎）。
- **影响**：`package.json` 依赖、F-04 工时（A=8h / B=11h / C=15h）、I1.5 容量、离线可用性。

## §3 未提问项：我按以下默认执行（有异议再改）

| 决策点 | 默认处理 | 理由 |
|---|---|---|
| 无截止日期的提醒 | `absent` 时**不设截止提醒**；状态为 `to_apply` 时退化为"投递后 T+7 跟进" | 无截止时间就无倒计时；跟进提醒仍有价值，且可配置 |
| 表格中缺失值的显示 | `deadline`/`剩余天数` 留空；`text_only` 在备注列显示"原文：招满为止" | 空 = 未知，不用"未提供"污染数据列 |
| 工作区路径 | `.env` 的 `WORKSPACE_DIR`（默认 `./data/workspace`）+ 设置页可改 | 与现有 14 项环境契约一致 |
| 同步触发 | `npm run sync`；应用内改动后自动导出（不自动回读） | 回读时机由用户掌控，避免与 Excel 抢文件 |
| 技能长表编辑 | 只读；技能编辑走主表 `技能(显式)` 列 | 长表是透视视图，双向编辑会放大冲突面 |
| 推测技能熟练度 | 一律 `unknown` | 推测只能说"可能要"，不能说"要到什么程度" |
| CSV 编码与安全 | UTF-8 **带 BOM**；RFC4180 转义；`=`/`+`/`-`/`@` 开头前置 `'` | 中文乱码与 CSV 注入都是高发问题 |
| 隐含预测实现 | 规则图谱 `skill-graph.json` 打底 + LLM 补长尾 | 与 F-01 的 L0–L4 一致：可离线、可复现、可单测 |
| 评测门槛 | 显式技能 F1 ≥0.85；**误推率 ≤15%**、覆盖率 ≥60% | 误推率比命中率更关键——推错会误导学习 |
| 标注集 | `evals/skills/` 100 条，≥30 条只给领域词 | 覆盖"隐含预测"新能力 |
| 截图输入默认引擎 | `OCR_MODE=auto`：有视觉模型走 VLM，否则给"手动粘贴"引导（Q-09 未裁决前的默认） | 零新依赖；实测不足再引入本地 OCR |
| OCR 结果进入抽取 | 识别文本走 F-02 **同一管线**，不做"图 → 结构化字段" | 避免第二条抽取链路与评测口径分叉 |
| 截图附件 | 存 `原始JD/attachments/`，删岗位时一并删 | 可追溯且只在本地 |
| 多图与长图 | 上限 5 张；长截图自动纵向切片（重叠 10%） | 覆盖手机长截图等主要场景 |
